# P450 MID360 Independent Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans`; apply TDD, review each implementation slice,
> and verify claims from fresh command output.

**Goal:** Add a reproducible, install-space P450 MID360 sensor profile and
prove its point stream and TF in the already-stable standalone P450 runtime,
without changing the default D435 gate or introducing mapping/benchmark work.

**Architecture:** Keep the single worldless `p450_runtime.launch` and its one
vehicle spawn. A new `enable_mid360` argument selects either the existing
`p450_D435i` SDF or the combined `p450_D435i_mid360` SDF while preserving the
same `/uav1` namespace, model identity, PX4 instance, MAVROS node, controller,
and camera TF publishers. Build the Livox Gazebo plugin from the local P450
source against the host-discovered Gazebo/Protobuf ABI. Install the four-file
MID360 model closure into a platform-owned `sim_platform_assets` package and
put that package first in the explicit Gazebo model path. A MID360 smoke profile
reuses the bounded standalone harness but accepts MID360 solely from its own
message, TF, plugin, and asset evidence; D435 remains the default regression
gate, not a prerequisite assertion for MID360 acceptance.

**Tech stack:** ROS Noetic, Catkin Tools install space, Gazebo Classic 11,
PX4 SITL, MAVROS, CMake, C++17, Bash, Python 3.8 `unittest`, ROS TF2 tools, ELF
`readelf`/`ldd` inspection.

**Write boundary:** All writes stay below
`/media/lu/P450_PAPER/SIM/p450_sim_v1`. The source model under
`/media/lu/P450_PAPER/P450-PAPER` and the external PX4/SITL checkouts are
read-only. `config/import_provenance.json` is immutable.

**Non-goals:** Do not add Fast-LIO, Octomap, 2D LiDAR, indoor PX4 profiles,
flight behavior, Ground runtime, shared-world integration, MoveIt, task
orchestration, RBP, Task-aware methods, M5, Pilot/T2/Formal, or paper evidence.

### Step 1: Add a strict profile switch to the shared harness

Keep `scripts/smoke_p450_standalone.bash` defaulting to `d435`. The thin
MID360 entrypoint selects only `mid360` and delegates to the common bounded
startup/shutdown machinery. Reject any other profile before launching ROS.

Both profiles retain the common gates: Gazebo server live, exactly one P450,
exact PX4/SITL repository state, one PX4 startup, MAVROS connected, controller
state valid, TF authority uniqueness, atomic `result.json`, bounded process
group shutdown, and no residual process.

### Step 2: Define independent MID360 acceptance

For the MID360 profile, require:

- launch argument `enable_mid360:=true`;
- `/uav1/livox/lidar` has type `prometheus_msgs/LivoxCustomMsg`;
- at least three messages with nonzero, increasing stamps,
  `point_num == len(points) > 0`, a nonempty point array, and
  `frame_id == "uav1/lidar_link"`;
- current-time TF `uav1/base_link -> uav1/lidar_link` matches the configured
  translation/rotation within a declared tolerance;
- exactly one TF authority owns `uav1/lidar_link`;
- the live Gazebo process maps the canonical local Livox plugin and
  `libprotobuf.so.17`, never `.9`;
- the plugin-resolved scan CSV and DAE are the installed SIM assets with ledger
  hashes.

Do not require D435 sample counts for the MID360 verdict. Record
`sensor_profile`, canonical asset/plugin paths, ABI evidence, topic samples,
and TF evidence in `result.json`.
